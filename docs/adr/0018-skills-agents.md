# ADR 0018 · Skills and agents: a section to list, create, edit and delete them; "/" in every chat input

Date: 2026-10-12 · Status: accepted

## Context
The user (12/10): "aggiungi il supporto per le skill, deve anche essere facile dall'app creare e modificare skill una
sezione apposta, anche per gli agenti." Skills and subagents are markdown files with a YAML frontmatter that each CLI
reads by itself: Claude Code `~/.claude/skills/<name>/SKILL.md`, `~/.claude/agents/<name>.md` and the same under a
project's `.claude/`; Cursor the same shapes under `~/.cursor/` and a project's `.cursor/`. Writes to the user's brain
pass through the brain's PreToolUse hook `brain-limits.mjs` (fixed-context budget): the app must show that hook's
refusal or keep the same limit, never get around it.

Probed 12/10 (CLI 2.1.282): an app chat (stream-json input) already runs a skill when the message starts with
`/<name>`, as a string or as content blocks; the `initialize` control response and the `commands_changed` system
message list the chat's commands with description and argument hint. Cursor's ACP sends `available_commands_update`.

## Decision
- **One section "Skill e agenti"** (`G S`, sidebar under Cervello): every skill and agent of Claude and Cursor, user
  level and project level. Project folders = the brain folder and the folders of the app's chats (a git worktree is
  left out: its files are its main repo's, on another branch). Name, description, engine, where, a validity mark.
- **Create, edit, delete** with a form (name, description, instructions; tools and model for an agent) and a markdown
  editor of the whole file with its frontmatter checked live (`src/shared/skillmd.ts`, the same check in main before
  writing: name lowercase letters, digits and hyphens up to 64, description required up to 1024 chars, frontmatter
  closed, no duplicate keys). The form changes only its own fields: other frontmatter keys stay as they are. A new
  name moves the skill folder (or renames the agent file). A file changed on disk since it was opened is not
  overwritten.
- **Writes go through the user's own PreToolUse hooks**: before writing, main runs every PreToolUse command hook whose
  matcher matches `Write` (user `~/.claude/settings.json`, and the project's `.claude/settings.json` /
  `settings.local.json`) with the same JSON a `Write` tool call would give it. Exit 2, `decision: block` or
  `permissionDecision: deny` refuse the save and the UI shows the hook's message as is; like Claude Code, a hook that
  crashes or times out does not block. The app reads these settings, never changes them (AGENTS.md rule 6). Today
  `brain-limits.mjs` covers no skill or agent file, so it always passes; if it ever does, the app follows it.
- **Read-only entries**: files generated by another tool (an `<!-- Generated by … do not edit -->` line, e.g. the
  brain's `sync-agents.mjs` copies in `~/.claude/agents`) show where their source is and cannot be saved from the app;
  plugin skills (`~/.claude/skills/synced`, `~/.cursor/skills-cursor`) are not listed.
- **Delete = Windows Recycle Bin** (`shell.trashItem`): a skill's whole folder, an agent's file. Always after a
  confirmation.
- **"/" in every chat input**: typing `/` at the start opens the list of that chat's commands, filtered as you type
  (↑↓, Tab or Invio completes `/<name> `, Esc closes). Source: the commands the chat's own engine reported
  (`initialize` / `commands_changed` for Claude, `available_commands_update` for Cursor), kept in memory per chat;
  before the engine said anything, the skills of that engine found on disk for the chat's folder. The message goes
  to the engine as typed: the engine runs the skill (no tokens spent by the app).

## Consequences
- No new dependency: the frontmatter reader is a small YAML subset (scalars, quoted strings, `>`/`|` blocks, lists);
  anything else is kept verbatim and never rewritten.
- Running the user's hook commands is what the CLI already does on every `Write`; nothing else from settings runs.
- The section edits files the CLIs read live: a saved skill is offered by a chat's "/" list after its engine reloads
  (Claude: next chat, or `/reload-skills`).
