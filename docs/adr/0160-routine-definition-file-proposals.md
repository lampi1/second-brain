# 0160 — Large routine proposals from brain JSON files

Large self-contained definitions should not need to fit into one model tool-call payload. `app_flow_propose` accepts exactly one of `definition` or `definitionPath`, plus the existing `contextKey` and `expectedRevision`. The path may be relative to the selected brain or absolute inside it. This focused transport change needs no multipart upload state.

Read only a regular, single-link `.json` file of at most 1 MiB. Reject traversal, paths outside the current brain, symbolic links/junctions, alternate streams, invalid UTF-8/JSON and files changed while opening or reading. Pin directory identities and nanosecond change metadata from the filesystem root through every ancestor and file parent, including swaps restored between path checks. Bound the actual read, not just its initial stat; do not echo filesystem paths or parser excerpts on errors. The file contains the plain definition object, not an export or tool-call envelope.

The authenticated Orchestrator and context checks run before reading. Recompute the canonical root identity with the same helper used by the runtime and require it to match that service's context before opening the file; a newly redirected brain path is not a trusted new root. Submit the parsed object through the existing `FlowService.propose`; `validateDefinition`, `brainReference`, field/package limits, role/model checks and exact revision checks remain unchanged. Store a snapshot of the validated definition, never a runtime reference to the source file. No activation, execution or grant is implied. The user still approves the exact draft in Routine.

File mode returns a compact receipt (flow ID/title, revision/status/time, definition digest and step count) instead of sending the large source back into model context. Inline calls retain their previous result. The full draft remains visible in Routine. The on-demand capability catalog documents the new transport; there is no new always-on prompt.

Unrelated sibling activity can change ancestor metadata, especially in shared temporary folders. Discard any such read and retry from canonicalization with the same authenticated context, up to five total attempts. Every attempt repeats all identity, path, size and content checks. Identity changes, links, file mutation and invalid data remain immediate refusals; continuing metadata instability also refuses. There is no unchecked fallback.

Validation covers a synthetic definition larger than 88,000 characters, relative/absolute paths, both proposal modes, stale context/revisions, unchanged validation failures, immutable approval, filesystem confinement, encoding/size failures and authenticated app-control wiring. No private routine is copied into the public repository.
