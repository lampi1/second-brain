## PR #12: hybrid search (lexical + semantic over the brain)

### 1. Medium (security): gitignored brain files reach every agent when `git ls-files` fails
- **Where:** `src/main/search/hybrid/engine.ts:149-164` (`brainFiles`).
- **What goes wrong:** on any git error the file list falls back to a plain folder walk that ignores `.gitignore`.
- **Scenario:** the brain folder is owned by another account (git exits 128, "detected dubious ownership"), or git is
  not on PATH. Gitignored files such as `private/keys.txt` get indexed, and `brain_search` hands them to every chat.
  The brain's own site (`brain-site.mjs`) shows nothing in the same situation.
- **Proof:** `pr-12/gitignore-fallback.test.ts`, "still leaves gitignored notes out when git ls-files fails". It fails
  with `expected [ 'now.md', 'private/keys.txt' ] to not include 'private/keys.txt'`. The sanity test with git working
  passes.
- **Fix:** when the root is a git work tree but git fails, index nothing, keeping the walk only when there is no
  `.git`. Or apply `.gitignore` in the walk.

### 2. Medium (wrong results): meaning hits have no similarity floor
- **Where:** `src/main/search/hybrid/engine.ts:243-254`, `store.ts:145-153`.
- **What goes wrong:** the vector search always returns up to 60 chunks, whatever their cosine (0 or negative
  included), and all of them are fused as hits.
- **Scenario:** with e5, unrelated texts score around 0.7, so nonsense queries still return results:
  - Ctrl+K "Nel brain" always shows 6 unrelated files, and they replace the palette's own file hits
    (`search/service.ts:64`).
  - `/api/search` returns 50 places.
  - `brain_search` never tells an agent that an exact code is absent.
- **Proof:** `pr-12/no-similarity-floor.test.ts`, two tests:
  - "returns nothing for a query unrelated to every note" returns costs.md, errors.md and release.md, all via meaning.
  - "Ctrl+K shows no brain file for an unrelated query" fails the same way.
- **Fix:** a minimum cosine (calibrated for e5, or relative to the best hit). Drop weak meaning-only hits when no
  word matched.

### 3. Low: a model failure on the query embed fails the whole search instead of answering by words
- **Where:** `src/main/search/hybrid/engine.ts:243-246`.
- **What goes wrong:** `embedder.embed([q], 'query')` is awaited unguarded. Only the background pump disables a broken
  model.
- **Scenario:** until the pump disables the model:
  - every query rejects;
  - `brain_search` returns an error to the agent;
  - Ctrl+K and `/api/search` fall back to substring search.

  The ADR promises words-only results when the model fails.
- **Proof:** `pr-12/query-embed-failure.test.ts`, "still returns the words (BM25) hits". It fails with
  `expected 'query rejected: onnxruntime: Non-zero…' to deeply equal [ 'ai-errors.md' ]`.
- **Fix:** wrap the query embed in try/catch and continue with no semantic hits (log it, or mark the model failed).

### 4. Low: hits without the query words point at a blank line with an empty excerpt
- **Where:** `src/main/search/hybrid/engine.ts:281` with `chunk.ts:35-37`.
- **What goes wrong:** the chunker keeps the blank line between a short heading and its text. `bestLine`'s fallback
  picks the first non-heading line, which is that blank line.
- **Scenario:** with the usual "# Heading, blank line, text" layout, meaning-only hits, typo-widened hits and file-name
  hits come back as line N+1 with an empty excerpt. The excerpt is empty in Ctrl+K, in `/api/search` and in
  `brain_search`.
- **Proof:** `pr-12/blank-excerpt.test.ts`, two tests. Both fail with `expected { line: 2, text: '' } to deeply equal
  { line: 3, … }`.
- **Fix:** skip blank lines in the fallback: `findIndex(l => l.trim() && !/^#{1,6}\s/.test(l))`.

### 5. Low (resources): a briefly missing brain folder wipes the index and forces a full re-embed
- **Where:** `src/main/search/hybrid/engine.ts:146-165,195`, `store.ts:135-137`.
- **What goes wrong:** a missing root looks like an empty brain. `sync` removes every document, and the next idle
  pump prunes every vector.
- **Scenario:** a OneDrive or network folder, or a USB disk, is offline for a moment. When it comes back, every chunk
  is embedded again (minutes of CPU per the ADR), and searches find nothing in between. Switching brain A → B → A
  costs the same, because the index is shared rather than kept per brain.
- **Proof:** `pr-12/missing-root.test.ts`, "keeps the index (and its vectors) instead of treating the folder as
  empty". It fails with `expected { docs: 2, reEmbedded: 2 } to deeply equal { docs: 2, reEmbedded: +0 }`.
- **Fix:** if the root does not exist or listing fails, skip the sync without removing anything.

**Checked and fine:**
- Word folding matches FTS5 `remove_diacritics 2`.
- Dropping DirectML.dll is safe (it is delay-loaded).
- The runtime packages resolve through `createRequire`.
- Chunk line mapping and the typo early exit are correct.
- Worker requests are serialized.
- `brain_search` is on every chat's MCP endpoint, so it works the same for Claude, Codex and Cursor.

**Checks:** `npx tsc --noEmit` clean. `test/unit/hybrid-search.test.ts`, `brain/api.test.ts` and `search.test.ts`
pass (40/40). None of these tests is Windows-only.

## PR #18: search themes (recurring errors and ideas grouped by meaning)

### 1. Medium: stale themes after a same-length edit of a line (fixed later by #27)
- **Where:** `src/main/search/hybrid/service.ts:127` (#18 head).
- **What goes wrong:** the cache key is `${id}:${line}:${text.length}`. `Store.put` deletes and re-inserts a
  document's chunks without AUTOINCREMENT, so a re-indexed document that held the highest rowids gets the same ids
  back (`store.ts:89-93`).
- **Scenario:** an `ai-errors.md` line is corrected in place, for example its date, as the file's header asks. The id,
  line and length stay the same, so `themes()` keeps returning the old day and text until another edit or midnight.
- **Proof:** `pr-18/themes-cache-stale.test.ts`. It fails on ef4e450 with `themes still show the date before the
  correction: expected [ '2026-10-16', '2026-10-15' ] to include '2026-10-17'`. It passes on #27 (`rowsKey`).
- **Fix:** key on the content (a hash of each row's text), as #27's `rowsKey` does.

### 2. Low: the accented stop word «perché» is never filtered (still present in #27)
- **Where:** `src/main/search/hybrid/themes.ts:29-35`.
- **What goes wrong:** `fold()` strips accents before the `STOP` lookup, but `STOP` keeps `perché` (and `più`, `già`)
  accented.
- **Scenario:** "perche" survives and lands in theme labels, e.g. `costi · perche · stale`.
- **Proof:** `pr-18/themes-stopwords-accents.test.ts`. It fails with `expected [ 'costi', 'perche', 'stale' ] to not
  include 'perche'`, on #18 and on #27.
- **Fix:** build `STOP` through the same folding: `.map(w => w.normalize('NFD').replace(/\p{M}/gu, ''))`.

### 3. Low: crash when two overlapping calls overflow the text-vector cache (fixed later by #27)
- **Where:** `src/main/search/hybrid/service.ts:139-148` (`embedCached`, #18 head).
- **What goes wrong:** a call that pushes the cache past `TEXT_VECS_MAX` calls `clear()` while another call is still
  awaiting its batch.
- **Scenario:** the waiting call later reads `undefined` vectors, and `dot()` throws `TypeError` (`themes.ts:47`), so
  `/api/themes` answers an error. It needs a long session (about 5000 cached texts).
- **Proof:** `pr-18/themes-embed-cache-race.test.ts`. It fails on ef4e450 with `expected 'TypeError: Cannot read
  properties of …' to be 'ok'`. It passes on #27.
- **Fix:** keep each call's vectors in a local map, or evict only after the call ends, as #27 does.

**Checked and fine:**
- Clustering (Lance-Williams), ties and determinism.
- Empty and single input.
- The growing-theme baseline, with no division by zero.
- CRLF handling.
- The fallback when embedding fails.
- Brain-root switches.
- Engine-agnostic: it reads files only.

**Checks:** `npx tsc --noEmit` clean. `search-themes.test.ts` and `hybrid-search.test.ts` pass (30/30).

## PR #27: error recall (a warning when a prompt resembles a logged error)

### 1. Medium: an agent's permission ceiling is not enforced when Claude settings live in `CLAUDE_CONFIG_DIR`
- **Where:** `src/main/wiring.ts:347` (`env: { [RECALL_ENV]: recall.url() }`) with `src/main/chats/manager.ts:1798`
  (`claudeDefaultMode(r.s.cwd, this.opts.env ?? process.env)`).
- **What goes wrong:** before #27, `opts.env` was undefined, so `modeFor` read the real environment. Now it holds
  only `SB_APP_RECALL`, and `claudeDefaultMode` no longer sees `CLAUDE_CONFIG_DIR`.
- **Scenario:**
  1. The user's `$CLAUDE_CONFIG_DIR/settings.json` has `defaultMode: bypassPermissions`.
  2. They start an agent whose ceiling is `default`.
  3. `modeFor` reads `~/.claude` instead, finds nothing above the ceiling and passes no `--permission-mode`.
  4. The CLI does get `CLAUDE_CONFIG_DIR` (`claude.ts:282` merges `process.env`), so it starts in bypassPermissions.

  The manager pulls the mode back after init, but first-turn tool calls can run before that.
- **Proof:** `pr-27/recall-env-ceiling.test.ts`. It fails with `expected null to be 'default'`. The pre-PR control
  (env undefined) passes.
- **Fix:** `env: { ...process.env, [RECALL_ENV]: recall.url() }` in wiring. Or, more robust,
  `claudeDefaultMode(cwd, { ...process.env, ...this.opts.env })`.

### 2. Medium (engine parity): error recall works only for Claude chats
- **Where:**
  - `src/main/wiring.ts:347` passes `SB_APP_RECALL` to every engine (`manager.ts:1847,1906`).
  - The only consumer is the Claude hook `brain-template/.claude/hooks/correction-catch.mjs:23-40`. It is wired only
    in `harness/claude/settings.hooks.json` and returns early on Cursor input.
  - Cursor's `hooks.json` has no prompt-time consumer.
  - The template ships no Codex hook.
  - Nothing in `chats/codex.ts` or `chats/acp.ts` injects the warning.
- **Scenario:** a Codex or Cursor chat gets a task close to a logged error (for example quoting in `node -e` under
  PowerShell), and no warning is ever shown. The feature silently does nothing for two of the three engines.
- **Proof:** `pr-27/recall-claude-only.test.ts`, two structural tests (Cursor and Codex). Each fails with
  `nothing calls SB_APP_RECALL … expected [] to not deeply equal []`.
- **Fix:** for engines without a prompt hook, have the app call `hybrid.recall()` before sending a turn and prepend the
  same labelled warning, or ship a Codex UserPromptSubmit hook. If Claude-only is intended, say so in the ADR and stop
  passing the variable to the other engines.

**Checked and fine:**
- The similarity cut and the 30-error minimum.
- Ordering.
- Changed-file and brain-switch handling.
- The hook's 300 ms timeout and fallbacks.
- The `embedCached` race fix.

**Checks:** `npx tsc --noEmit` clean. The PR's tests plus the search area: 70 passed, 1 skipped. The skipped one is
`brain/guard.test.ts` "two paths that differ only in case", which needs a case-insensitive file system and is not
touched by this PR.
