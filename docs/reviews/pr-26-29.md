## PR #26: file viewer V3b (compare a file with a git revision)

### 1. Medium (security): the repository's own config can re-enable ssh, so its `core.sshCommand` runs on git < 2.44
- **Where:** `src/main/file-diff.ts:73-75`.
- **What goes wrong:** the only network guard is `-c protocol.allow=never`. A per-protocol `protocol.<name>.allow`
  beats it, even when it comes from the untrusted repository's own `.git/config`.
- **Scenario:**
  1. A folder is set up as a partial clone with a missing blob, `protocol.ssh.allow=always` and a `core.sshCommand`.
  2. The user clicks "Confronta".
  3. git fetches the missing blob and runs that command.

  The second guard, `GIT_NO_LAZY_FETCH`, only exists on git ≥ 2.44 and on the May-2024 security backports.
- **Proof:** `pr-26/transport.test.ts`, "a repository config with protocol.ssh.allow=always does not get its
  core.sshCommand run by Compare". A PATH wrapper drops `GIT_NO_LAZY_FETCH` to act as an older git. It fails with
  `the repository-chosen core.sshCommand ran: expected true to be false`. Also reproduced by hand with the PR's exact
  options: with the override the command ran; without it git stopped with `transport 'ssh' not allowed`.
- **Fix:** also pass `-c protocol.<p>.allow=never` for ext, ssh, git, http, https and file. Or refuse a config
  matching `/promisor|partialclone/i`, or require git ≥ 2.44.

### 2. Medium (security): `findRepo` follows links to a network share before checking them
- **Where:** `src/main/file-diff.ts:86,90,92-93`.
- **What goes wrong:**
  - `.git`, the `commondir` target and `.git/objects` are followed with `statSync` and `realpathSync`. When they are
    links to `\\host\share`, Windows connects and sends the user's credentials. The rest of the app checks links
    first (`linksToShare`, `open-path.ts`).
  - When the share does not answer, `real(objects) ?? path.join(common, 'objects')` falls back to the unresolved path.
    That path passes the share check, and git then reads through the link.
- **Proof:** `pr-26/find-repo-links.test.ts`:
  - "a .git/objects that is a link to a network share is refused, not read through its unresolved path" fails with
    `expected { …(2) } to be 'share'`.
  - "a .git that is a link to a network share is refused, not followed" fails with `expected null to be 'share'`.
- **Fix:** run `linksToShare` (an lstat/readlink check) on `.git`, the gitdir target, the commondir target and
  `objects` before any stat or realpath. Treat a failed realpath of `objects` as `'share'`.

### 3. Low: a file whose name starts with `..` counts as outside the repository
- **Where:** `src/main/file-diff.ts:121`.
- **What goes wrong:** `rel.startsWith('..')` also matches a tracked file named, for example, `..notes.md` at the
  repository top.
- **Scenario:** Compare on such a file says "Il file non è in un repository git."
- **Proof:** `pr-26/dotdot-name.test.ts`. It fails with `expected { kind: 'refused', reason: 'repo' } to match object
  { kind: 'diff', … }`.
- **Fix:** `rel === '..' || rel.startsWith('..' + path.sep)`.

### 4. Low: with no usable git, Compare says "Commit o ramo non trovato."
- **Where:** `src/main/file-diff.ts:71,123`.
- **What goes wrong:** when git is missing or cannot start (e.g. GitHub Desktop's bundled git, not on PATH), the
  failed `rev-parse` becomes `'ref'`, so the user is told the commit is missing. The PR's own `'git'` reason is never
  used for this.
- **Also:** on Windows the missing git is cached for the session (`gitPath = null`), so installing git needs a
  restart.
- **Proof:** `pr-26/no-git.test.ts`. It fails with `expected { kind: 'refused', reason: 'ref' } to not deeply equal …`.
- **Fix:** return `'git'` when `gitBinary()` is null or the spawn fails (ENOENT). Keep `'ref'` for a real non-zero
  exit.

**Checked and fine:**
- Compare and DiffView drop stale responses and terminate the worker on unmount or change.
- A jsdiff timeout shows as "slow"; CRLF against LF gives no hunks.
- The CSP allows the worker.
- The IPC goes through the sender check.
- Text is rendered by React only, never as HTML.
- The `localFile` refactor behaves as before.

**Checks:** `npx tsc --noEmit` clean. `test/unit/file-diff.test.ts` and `file-view.test.ts` pass (15/15); neither has
Windows-only tests. The e2e (`test/e2e/file-diff.spec.ts`) was not run: per AGENTS.md it runs only on main.

## PR #29: concept guide («Guida»)

### Code

#### 1. Medium: a double click on «Discutine» starts two agent chats
- **Where:** `src/renderer/components/GuidePage.tsx:20-36` (`discuss`) and `:67` (onClick). There is no in-flight
  guard.
- **Scenario:** the catalog has an explainer agent, and the user double-clicks or clicks again while `chat:create` is
  still running. Each click creates a chat with `agentId` (two chats, two runs), sets a draft, focuses it and toasts.
  `AgentStartDialog.tsx:47` guards the same call with `creating.current`. The Orchestrator path is unaffected:
  `setDraft` drops a duplicate draft.
- **Proof:** `pr-29/a-discuss-double-click.test.ts`. Two clicks give 2 `createChat` calls; 1 is expected.
- **Fix:** a module-level or per-card busy flag around `discuss()`, and disable the button while it runs.

#### 2. Low: explainer detection gives false positives
- **Where:** `src/shared/concept-guide.ts:747`. The regex `\b(explainer|explain|spiegazion\w*|spiega\w*)\b` is also
  tested against `role`.
- **Scenario:** main fills an empty role with the purpose (`src/main/agents/catalog.ts`, validate). An ordinary agent
  whose purpose reads "Scrive il codice e spiega le modifiche" or "…explain refunds" is taken as the explainer, and
  the first match in catalog order wins.
- **Proof:** `pr-29/a-explainer-detection.test.ts`, 2 failing tests.
- **Fix:** match the name or id only, on whole names (`^(explainer|spiegazioni)$`), or use an explicit marker such as a
  category or manifest tag.

**Checked and fine:**
- The agent chat is created with an empty prompt in the brain folder (run goal = title). A failed create falls back
  to the Orchestrator.
- It works on Codex and Cursor too: `profileCanStart` checks the agent's engine, and the Orchestrator draft names only
  MCP tools.
- The catalog is loaded before a click (Sidebar's `useAgents`).
- The longest draft is about 2.3k characters, under the 8000 limit.
- `G E` collides with nothing.
- Under a role composition the Guida is not listed twice.
- The it/en i18n keys match.
