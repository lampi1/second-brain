Title: feat(agents): add portable agent pack format and safe archive core

Implement the format foundation of ADR 0069: deterministic ZIP archives, bounded decoding, a validated app manifest, portable skills, Claude/Cursor/Agent Plugins manifests, generated Codex agents, and tool-specific directory exports. Import inspection accepts supported plugin layouts, standalone skills and agents; it lists foreign auto-executing configuration as ignored and separates script approval from content inspection.

User-agent know-how and pack identity persist in the catalog. Content-hash changes create behavioral versions; restoring a pre-know-how version removes the newer know-how. Export staging can use the shipped guard once per domain, failing closed for missing guard inputs and returning locations/rules without matched values.

Compatibility evidence (official documentation checked 2026-10-18):

- OpenAI documents root `plugin.json` with the Agent Plugins 1.0 schema and automatic discovery under `skills/`: https://developers.openai.com/plugins/build/plugins . Local marketplace installation is documented; installing a ZIP directly is not established. The generated Codex custom agent is installed through the separate Codex folder export, because the portable plugin standard does not discover custom agents.
- Cursor documents both `.cursor-plugin/plugin.json` and root `plugin.json`: https://cursor.com/docs/reference/plugins . Marketplace resolution explicitly looks for the Cursor manifest. Local ZIP installation, precedence when both manifests coexist outside that path, project-skill visibility in subagents and ignoring Claude-specific subagent keys remain unverified. Cursor-specific export emits only documented subagent keys: https://cursor.com/docs/subagents .
- Claude documents per-subagent effort: https://code.claude.com/docs/en/sub-agents . An installed Claude CLI is exercised with `plugin validate --strict` on the actual unzipped artifact. This validates the plugin manifest; it does not establish runtime preload semantics. One additive adjustment to the ADR's minimal Claude manifest is necessary: strict validation warns without `author`, so the generated manifest attributes the generator as `second-brain`, without exporting a person's identity.

Validation: pack round trips and three target layouts; script approval (including multiline commands), unsafe paths, duplicate aliases, CRC, ZIP64 indicators, symlinks, encryption, size/count/ratio bounds, TOML escapes, guard deny lists, and catalog persistence/restore regressions. Review caught hooks in optional skill frontmatter, escaped TOML Unicode, multiline dynamic-command removal and restore-to-pre-know-how behavior; each is fixed and regression-covered.

Scope: core only. IPC, application flows, probation, preset editing, scheduler integration and UI follow in the stacked branches. No renderer behavior changes and no e2e run on this branch. Cross-host layouts are tested; actual Cursor/Codex runtime installation is not claimed.
